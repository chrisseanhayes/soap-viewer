Understanding the Layers

1. The Proxy/Stub Generation

In SOAP architectures, clients rarely build raw XML manually. They consume a WSDL (Web Services Description Language) file provided by the server to generate a strongly-typed proxy class.

2. The SOAP Envelope Structure

The core of SOAP is the Envelope. It acts as the outermost container. The Header is used for meta-information like routing directives, authentication tokens (WS-Security), or transaction context. The Body contains the actual business payload.

3. OSI Layer 7 (Application Layer)

SOAP is an application-layer protocol. Unlike lower-level TCP sockets, SOAP messages are typically tunneled over other Layer 7 protocols like HTTP (most common), SMTP (email), or message queues (JMS). Because it rides on top of HTTP, it easily passes through standard corporate firewalls.

4. Server-Side Validation

Before the server's business logic runs, the SOAP engine parses the XML and validates it strictly against the WSDL and XML Schemas (XSD). If a required element is missing, the server rejects the request at the boundary, often returning a structured SOAP Fault.
